# Configuration reference

The private runtime configuration lives under `workspace/config/`.

## `candidate.yaml`

Normally generated by `phd-agent ingest`, then reviewed by the user.

Important sections:

- `education`: degrees and thesis information;
- `research_interests`: research domains the candidate can truthfully claim;
- `methods`: methods actually used/studied;
- `skills`: grouped technical skills;
- `publications`: preserve real publication state;
- `projects`: relevant research/software projects;
- `languages`: language evidence;
- `supported_claims`: concise facts the Application Agent may reuse safely.

## `search_preferences.yaml`

### Funding

```yaml
funding:
  fully_funded_only: true
  tuition_waiver_required: true
  stipend_required: true
  minimum_stipend:
    amount: 2500
    currency: EUR
    period: month
  minimum_funding_years: 4
```

The filter intentionally does not perform hidden FX conversion. If a minimum is specified in EUR and a vacancy advertises CHF, the opportunity becomes `REVIEW` until the user compares the packages or extends the code with an explicit FX policy.

### Locations

```yaml
locations:
  allowed_countries: [Netherlands, Germany, Switzerland]
  preferred_countries: [Netherlands, Switzerland]
  excluded_countries: []
  preferred_cities: []
  excluded_cities: []
```

`allowed_countries` is a hard constraint. `preferred_countries` influences semantic fit/ranking rather than automatic rejection.

### Research

```yaml
research:
  required_topics: [autonomous systems]
  preferred_topics: [robotics, control systems]
  excluded_topics: []
  preferred_methods: [model predictive control]
  excluded_methods: []
```

Required/excluded items are hard filters when the opportunity has been sufficiently verified.

### Position type

```yaml
position:
  allowed_types:
    - salaried_phd
    - fully_funded_studentship
    - scholarship
  named_supervisor_required: false
```

Position types are normalized strings. If the type is unknown and a hard allowed list exists, the opportunity becomes `REVIEW` rather than being guessed.

### Application constraints

```yaml
application:
  avoid_mandatory_gre: true
  maximum_application_fee: 0
  english_only_acceptable: true
  custom_deal_breakers:
    - security clearance
```

Custom deal-breakers are literal semantic phrases checked against verified requirements/topics/methods. Use them sparingly and explicitly.

### Deadlines

```yaml
deadlines:
  earliest_deadline: null
  latest_deadline: 2027-12-31
  minimum_days_remaining: 14
```

`minimum_days_remaining` protects against discovering a great position too late to prepare a responsible application.

### Start date

```yaml
start_date:
  earliest: 2027-01-01
  latest: 2027-10-01
```

If the advertised start date is unknown, no hard start-date failure is invented.

### Automation

```yaml
automation:
  discovery_interval_hours: 24
  maximum_new_positions_per_cycle: 20
  auto_research_priority_threshold: 8.0
  auto_prepare_application_threshold: 8.7
  auto_prepare_applications: true
  require_verified_funding_before_preparation: true
```

`auto_prepare_applications` means "prepare drafts and queue approval" — it does not mean "submit without the user."

## `scoring.yaml`

Weights control ranking only after hard-filter evaluation. They can be changed to match the applicant's priorities. Do not interpret the resulting score as an admission probability.
